# 🍞 브레드이발소 재고관리

GitHub Pages(HTML 화면)와 Google 시트(데이터 저장)로 돌아가는 매장 재고 시스템입니다.

```
[휴대폰/PC 브라우저]  ──  index.html (GitHub Pages)
          │  요청
          ▼
[Google Apps Script 웹 앱]  ──  Code.gs
          │  기록
          ▼
[Google 시트]  상품 · 거래 · 일별요약 · 2026-09-17 · 2026-09-18 …
```

## 기능

- **판매(결제):** 상품을 담아 한 번에 결제하면 결제번호가 생기고 재고가 자동으로 줄어듭니다. 바코드 스캔 후 Enter로도 담을 수 있습니다.
- **재고:** 전산재고 옆에 직접 센 **실사 수량**을 입력합니다. 두 수량이 다르면 행이 **빨간색**으로 바뀌고 “재확인” 표시가 붙습니다. 구글 시트에서도 같은 행이 빨간색으로 보입니다. “맞추기”를 누르면 전산재고를 실사 수량으로 바꾸고, 그 차이를 ‘조정’으로 기록합니다.
- **기본 상품 자동 채우기:** `Code.gs`의 `SEED_PRODUCTS`에 상품을 더하고 바로 위의 `SEED_VERSION` 숫자를 1 올리면, **다음 접속 때 빠진 상품만 자동으로 등록**됩니다. 기존 상품·재고는 건드리지 않고, 여러 번 접속해도 중복되지 않습니다.
  - 수동으로 하려면 화면 **⚙️ 설정 → 기본 상품 확인 → 빠진 기본 상품 추가**, 또는 시트 메뉴 **재고관리 → 기본 상품 다시 확인 (빠진 것만 추가)**.
  - 예전에는 `SEEDED` 표시 때문에 처음 한 번만 등록되어, 나중에 추가한 상품(봉투 등)이 들어가지 않았습니다. `SEED_VERSION`으로 해결했습니다.
  - **코드가 겹치면 등록되지 않습니다.** 기본 목록의 코드를 매장에서 다른 상품에 이미 쓰고 있으면 그 상품은 건너뜁니다. 이 경우 접속 안내와 🩺 자가 점검에 `코드 BB028가 이미 "키캡 3구 키체인"로 쓰이고 있어 …` 처럼 표시되니, 기본 목록 쪽 코드를 바꾸세요.
- **입고·상품:** 입고를 등록하고 상품을 추가합니다. 인포스페이스 `창고매장재고` 엑셀을 올리면 전산재고를 한꺼번에 반영합니다.
- **일별 리포트:** 날짜별로 결제 건수, 판매 수량, 매출, 결제당 평균 금액, 환불을 보여 줍니다. 결제별 상세 내역(무엇을 몇 개, 얼마에 팔았는지)과 상품별 판매 순위도 볼 수 있고, 결제 단위로 환불하면 재고가 복원됩니다.
- **자정 자동 보관:** 매일 **00시**에 전날 내역을 `2026-09-17` 같은 날짜 이름의 새 시트로 내보냅니다. 새 시트에는 요약, 결제별 판매, 상품별 판매, 마감 재고(불일치는 빨간색), 전체 거래가 들어갑니다. `일별요약` 시트에도 한 줄씩 누적됩니다.
  - 구글 트리거의 특성상 실행 시각은 **00:00~01:00 사이**입니다.
- **바코드 읽기 (PC):**
  - **USB/무선 바코드 스캐너:** PC에 꽂기만 하면 됩니다. 어느 화면에서든 찍으면 현재 탭에 맞게 처리됩니다.
    - 판매 탭: 결제에 담기
    - 입고·상품 탭: 입고 목록에 +1
    - 재고 탭: 해당 상품을 찾아 실사 칸으로 이동. 수량을 입력하고 Enter를 누르세요.
    - 등록되지 않은 바코드: 경고음이 나고, 상품 추가 칸에 바코드가 미리 채워집니다.
  - **웹캠:** 상단의 📷 카메라 스캔 버튼을 누르세요. 처음 한 번 카메라 권한을 허용해야 합니다.
  - 스캐너는 "숫자 입력 후 Enter"(키보드 모드)로 설정되어 있어야 합니다. 대부분 기본값입니다.
- **빠른 저장:** 결제·입고·실사 입력은 화면에 바로 반영되고, 구글 시트에는 뒤에서 순서대로 저장됩니다. 상단 배지로 상태를 확인할 수 있습니다(✓ 저장됨 / ⏳ 저장 중 / ⚠ 재시도 중).
  - 인터넷이 끊기면 입력한 내용을 브라우저에 보관해 두었다가 자동으로 다시 보냅니다.
  - 같은 요청이 두 번 저장되지 않습니다.
- **마감하기 (인터넷이 불안정한 매장용):** 기본 설정은 기록을 기기에 보관해 두었다가, 🏁 **마감하기**를 누를 때 구글 시트에 한꺼번에 업로드하는 방식입니다.
  - 업로드가 끝나면 날짜 시트도 바로 만듭니다.
  - 실패해도 기록은 기기에 남고, 다시 눌러도 같은 기록이 두 번 올라가지 않습니다. 업로드 시각이 아니라 실제로 판매한 시각으로 기록됩니다.
  - 설정 탭에서 "바로바로 자동 저장"으로 바꿀 수 있습니다.
- **실사 (하루 두 번):** 재고 탭 맨 아래 ✅ 실사 완료 저장, 또는 상단 🌅 오픈 점검 · 🏁 마감하기 (같은 창, 창에서 오픈/마감 선택). 두 버튼 모두 업로드 → 전산재고를 실사 수량으로 맞춤(차이는 '조정(오픈/마감 실사)' 기록) → **실사 칸 초기화**로 처리되고, 마감에서만 날짜 시트 보관까지 합니다. 결과는 `실사기록`(상품별)과 `실사요약`(점검별: 날짜·구분·일시·담당자·불일치수·차이금액) 탭에 누적되고, 일별 리포트에서도 오픈/마감 실사를 볼 수 있습니다. 마감 창에서 "실사 수량으로 전산재고 맞추기" 체크를 끄면 맞추지 않고 마감만 합니다.
  - **날짜별로 구분되게 저장:** 실사기록·실사요약은 점검 한 번이 하나의 **상자(테두리)** 로 묶이고, **날짜가 바뀌는 자리에는 굵은 가로선**이 들어갑니다. 날짜마다 배경색이 번갈아 바뀌고, 오픈은 파란색·마감은 주황색 글씨, 차이가 난 줄은 빨간색입니다.
  - 이미 쌓여 있던 기록은 시트 메뉴 **재고관리 → 실사 시트 보기 좋게 (날짜별 테두리)** 를 한 번 누르면 같은 서식이 입혀집니다.
  - 날짜 시트에는 **재고 점검 (오픈 · 마감)** 표가 들어가, 상품마다 `오픈 전산 / 오픈 실사 / 오픈 차이 / 마감 전산 / 마감 실사 / 마감 차이 / 보관 시점 재고`를 한 줄에서 비교할 수 있습니다. 오픈이나 마감 중 하나라도 차이가 나면 그 줄이 빨간색입니다.
- **바코드 점검:** 재고 탭의 🔎 바코드 점검에서 상품 바코드를 하나씩 찍어 등록된 바코드와 일치하는지 확인합니다. 미등록 바코드는 상품을 골라 바로 등록할 수 있고, 결과는 `바코드점검` 탭에 기록됩니다.
- **오프라인 모드:** 구글 응답이 늦으면 마지막으로 받아 둔 상품 목록으로 바로 판매할 수 있고, 20초마다 다시 연결을 시도합니다.
- **매출 대사 (카드 단말기와 맞춰보기):** 일별 리포트 탭의 💳 **매출 대사**에 단말기 정산 합계를 넣으면 시스템 매출과의 차이를 계산하고, 차이가 난 방향에 맞는 **확인해 볼 곳**을 순서대로 보여 줍니다. 기록은 `매출대사` 시트에 날짜·시각·담당자·메모와 함께 누적되고 날짜 시트에도 들어갑니다.
  - 시스템이 **적을** 때: 아직 업로드하지 않은 기록(이 기기 또는 다른 기기), 카드만 긁고 시스템에 안 찍은 결제.
  - 시스템이 **많을** 때: 중복 결제, 단말기에서 취소했는데 시스템에 남은 결제.
  - 마감하기가 끝나면 그 자리에서 **오늘 매출**이 바로 표시되고, 지난 날짜 기록이 기기에 남아 있으면 화면 위에 빨간 경고줄이 뜹니다.
- **영수증 직접 입력 / 결제 수정:** 일별 리포트 탭의 🧾 **영수증 직접 입력**에서 **날짜·시각**을 지정해 판매를 기록합니다. 봉투처럼 뒤늦게 등록한 상품, 티켓 등록 전 영수증, 가격이 다르게 들어간 결제를 나중에 보정할 때 씁니다.
  - 줄마다 **상품명(고르기) · 수량 · 금액 · 비고**를 넣습니다. **금액은 영수증에 찍힌 금액 그대로** 넣으면 됩니다 (단가를 계산할 필요 없음). 비우면 `등록된 판매가 × 수량`이 자동으로 들어갑니다.
  - 비고는 줄마다 따로 남길 수 있고, `거래` 시트의 메모 칸에 그대로 저장됩니다.
  - **재고도 함께 차감** 체크를 끄면 매출만 기록하고 재고는 건드리지 않습니다 (그 날짜를 실사로 이미 맞춘 경우).
  - 결제별 판매에서 결제를 펼쳐 **✏️ 수정**을 누르면 그 결제의 수량·금액을 고칠 수 있습니다. 상품을 빼거나 새로 넣을 수도 있고, 재고는 **차이만큼만** 조정됩니다. 날짜·시각은 원래 결제 그대로 유지됩니다.
  - **🗑 잘못 넣은 결제 지우기:** 손님에게 환불한 게 아니라 **입력을 잘못했을 때** 씁니다. 그 결제를 없던 일로 만들어 **원래 날짜 매출에서 빼고 재고를 되돌립니다**. 거래 줄은 남기고 수량·금액만 0으로 바꿔 이력이 보존됩니다.
  - 손님에게 돈을 돌려준 경우는 지우기가 아니라 **환불**을 쓰세요. 이미 환불된 결제는 수정·지우기가 막힙니다.
- **↩️ 환불 직접 입력 (수량을 모를 때):** 영수증 카드 위의 **판매 기록 / 환불 기록** 단추로 바꿉니다. 반품 영수증에 **금액만** 찍혀 있어도 기록됩니다.
  - **금액만** 넣으면 그 날짜 매출에서 금액만 빠지고 재고는 건드리지 않습니다. 거래 시트에는 `(상품 미상)` · 수량 0 · 메모 `수량 모름`으로 남습니다.
  - 무엇을 몇 개 돌려줬는지 알면 **상품과 수량**까지 넣으세요. 그때만 재고가 그만큼 돌아옵니다 (체험 티켓은 원래 재고가 없어 그대로).
  - 기존 결제를 통째로 되돌리는 **환불**(결제별 판매의 빨간 버튼)과 달리, 이건 **결제를 특정하지 못할 때** 쓰는 보정 입력입니다. 날짜·시각을 직접 지정하므로 지난 날짜도 정확히 반영됩니다.
- **⚠️ 불량 환불 (재고로 돌아오지 않음):** 돈은 돌려줬지만 **상품을 다시 팔 수 없는** 경우입니다. 재고로 되돌리면 실사가 틀어지므로 **재고는 그대로 둡니다**.
  - 환불 직접 입력의 **환불 사유**에서 `⚠️ 불량 · 다시 못 팜`을 고르면, 재고 되돌리기 체크가 자동으로 꺼지고 잠깁니다.
  - 결제별 판매에서는 **↩️ 환불 (재고 복원)** 과 **⚠️ 불량 환불 (재고 그대로)** 두 버튼 중에 고릅니다.
  - 불량은 `불량` 시트에 `날짜 · 일시 · 코드 · 상품명 · 수량 · 환불금액 · 결제번호 · 담당자 · 메모 · 구분`으로 따로 쌓입니다. 업체에 불량 청구할 때 그대로 쓰시면 됩니다.
  - 일별 리포트에 **불량 환불 N개 · 금액**이 표시되고, 날짜별 보관 시트에도 **불량 환불** 표가 들어갑니다.
- **🔁 교환 (매출에 영향 없음 · −0원):** 돈은 오가지 않고 **같은 값의 새 물건으로 바꿔 준** 경우입니다. 환불로 잡으면 그날 매출이 깎이므로, 교환은 **매출 0원**으로 기록합니다.
  - 거래 시트에는 유형이 `환불`이 아니라 **`교환`**, 금액은 **0원**으로 남습니다. 그래서 그날 매출·환불액·결제 건수·매출 대사가 전혀 바뀌지 않습니다.
  - **재고는 새로 내준 만큼 빠집니다.** 받은 불량품은 팔 수 없으므로 재고로 돌아오지 않고, 새 물건 한 개가 나갔으니 재고 −1 입니다. 이렇게 해야 마감 실사와 맞습니다.
  - 환불 직접 입력의 **환불 사유**에서 `🔁 교환 · 매출 그대로`를 고르거나, 결제별 판매에서 **🔁 교환 (매출 그대로)** 버튼을 누릅니다.
  - `불량` 시트에 **구분 = 교환**으로 쌓입니다. **같은 날짜·시각·상품으로 다시 넣으면 그 줄을 덮어씁니다** — 손으로 잘못 적어 둔 줄도 지우지 않고 그대로 바로잡을 수 있습니다. **팝업이 끝나면 이 목록을 업체에 환불용으로 청구**하시면 됩니다.
  - 일별 리포트에 **교환 (업체 청구) N개 · 금액**이 표시되고, 날짜별 보관 시트에도 **교환 (매출 0원 · 팝업 끝나고 업체에 청구할 몫)** 표가 따로 들어갑니다.
  - **↩️ 환불 · 교환 내역 (구분 바로잡기):** 일별 리포트 아래에 그 날짜의 환불·교환 줄이 모두 나옵니다. 구분을 잘못 넣었으면 **변심 / 불량 / 교환** 중 하나로 바꾸면 됩니다 (🔑 `0921` 필요).
  - **교환으로 바꾸면** 그 줄이 **0원**이 되어 그날 매출이 그만큼 되살아나고, `불량` 시트에 **구분 = 교환**으로 올라갑니다.
  - **재고는 바뀐 구분의 차이만큼만** 조정합니다 (변심 +1 / 불량 0 / 교환 −1 기준). 이미 실사·조정으로 맞춰 둔 날짜면 **재고 체크를 끄고** 바꾸세요.
  - **재고 체크는 지난 날짜면 기본으로 꺼집니다.** 지난 날짜는 마감 실사로 이미 맞춰져 있는 게 보통이라, 켜면 같은 한 개가 두 번 빠집니다. 그날 그 상품을 실사·조정으로 손봤으면 목록에 빨간 경고가 뜨고 확인창에서도 한 번 더 막아 줍니다.
  - 확인창에 **재고가 몇 개 움직이는지 미리 보여 줍니다** (예: `백팩25cm/마카롱 재고 -1`).
  - 잘못 눌러도 다시 **변심**으로 되돌리면 금액·재고·불량 시트가 원래대로 돌아갑니다. 바꾼 내역은 `수기수정` 시트에 `구분 바로잡음`으로 남습니다.
- **🔑 기록 수정 비밀번호 `0921`:** 이미 저장된 결제를 **수정**하거나 **지울** 때만 따로 묻습니다. 입장 비밀번호(`1998`)와 다릅니다. 판매·입고·실사·환불·영수증 신규 입력은 비밀번호 없이 그대로 씁니다.
    - 값은 `Code.gs` 맨 위 `const DEL_PIN = '0921';`. 화면 쪽이 아니라 **구글 시트 쪽에서 확인**하므로 화면을 고쳐도 통과되지 않습니다.
  - **중복 방지:** 같은 요청이 두 번 들어와도 한 번만 처리됩니다. 캐시와 `_처리기록` 시트 두 곳에서 확인하므로, 캐시가 비워져도 중복되지 않습니다.
  - 기록한 내용은 `수기수정` 시트에 남습니다 (일시·구분·대상 날짜·결제번호·내용·금액 변화·재고 반영·담당자·메모).
- **판매가 점검 (수량은 맞는데 금액이 안 맞을 때):** 상품 메모에 `소비자가 9,900`처럼 적혀 있으면 등록된 판매가와 비교합니다. 등록 판매가가 행사가/공급가로 들어가 있으면 매출만 실제보다 적게 잡힙니다.
  - 시트 메뉴 **재고관리 → 💰 판매가 점검 (메모의 소비자가와 비교)**: 다른 상품 목록을 보여 주고 "예"를 누르면 판매가를 소비자가로 바꿉니다.
  - 시트 메뉴 **재고관리 → 💰 지난 매출 판매가로 다시 계산**: 이미 저장된 `거래` 줄의 단가·금액을 현재 판매가로 고치고, 날짜별 변화량을 먼저 보여 준 뒤 확인을 받습니다. 날짜 시트와 `일별요약`도 다시 만듭니다. 체험 티켓(TK)은 건드리지 않습니다.
  - 바꾼 내용은 `판매가수정` 시트에 남습니다.
  - 매출 대사 결과에도 이 원인이 함께 뜨고, **💰 판매가 점검 열기** 버튼으로 차이 나는 상품을 바로 볼 수 있습니다.
- **봉투:** `PK001 봉투 200원`. 포장 자재는 매장에서 쓰는 `BB0xx` 번호와 겹치지 않도록 `PK` 코드를 씁니다. 일반 상품이라 팔면 재고가 줄어듭니다. 메모에 `고정`이 들어 있어 판매 탭에서 티켓 바로 뒤에 고정으로 표시됩니다 (다른 상품도 메모에 `고정`을 넣으면 앞쪽으로 나옵니다).
- **체험 티켓:** 코드가 `TK`로 시작하는 상품은 재고를 차감하지 않습니다. 기본으로 `TK001` 사전예약(현장결제) 9,000원, `TK002` 현장예약 11,000원, `TK003` 할인가 4,000원이 등록됩니다.
  - 판매 탭 맨 앞에 티켓 카드가 나오고, 인원 수만큼 담아 결제합니다.
  - 일별 리포트에 **시간대별 인원**과 체험 인원·매출이 따로 표시되고, 날짜별 보관 시트에도 저장됩니다.
- **샘플 모드:** 연결 설정 전에는 샘플 상품으로 모든 기능을 미리 써 볼 수 있습니다. 샘플 데이터는 이 브라우저에만 저장됩니다.

## 설치 (약 10분)

### 1. 구글 시트 + Apps Script

1. 새 Google 시트를 만듭니다. 이름은 예를 들어 `브레드이발소 재고`로 합니다.
2. **확장 프로그램 → Apps Script**를 엽니다. 기본 코드를 지우고 `apps-script/Code.gs` 내용을 붙여넣은 뒤 저장합니다.
3. 위쪽 함수 선택에서 **`setup`**을 고르고 **실행**합니다. 권한 요청이 나오면 허용합니다.
   - `상품`, `거래`, `일별요약` 시트가 만들어지고 자정 보관 트리거가 등록됩니다.
4. **입장 비밀번호:** `Code.gs` 맨 위의 `const PIN = '1998';`에 들어 있습니다. 바꾸려면 이 값을 고치고 새 버전으로 배포하세요.
5. **배포 → 새 배포 → 유형: 웹 앱**을 선택하고 다음과 같이 설정합니다.
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 후 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해 둡니다.

> `Code.gs`를 고친 뒤에는 **배포 관리 → 수정(연필) → 버전: 새 버전**으로 다시 배포해야 반영됩니다. 이렇게 하면 URL은 그대로 유지됩니다.

### 2. GitHub Pages

1. GitHub에서 새 저장소를 만듭니다. 예: `bread-inventory`
2. `index.html`을 업로드합니다. `README.md`와 `apps-script/` 폴더도 함께 올려 두면 관리하기 편합니다.
3. 저장소에서 **Settings → Pages → Branch: `main` / `(root)` → Save**를 누릅니다.
4. 1~2분 뒤 `https://<아이디>.github.io/bread-inventory/`로 접속합니다.

### 3. 연결

웹 앱 URL은 `index.html`에 기본값으로 들어 있습니다. 화면을 열면 입장 창이 뜨니 **본인 이름**과 비밀번호 `1998`을 입력하고, **⚙️ 설정** 탭에서 **저장하고 연결**을 누릅니다. 상단 배지가 “구글 시트 연결됨”으로 바뀌면 완료입니다. 매장 휴대폰마다 한 번씩 설정하면 됩니다.

### 4. 첫 상품 넣기

다음 중 하나를 사용하세요.

- 인포스페이스에서 브레드이발소 `창고매장재고` 엑셀을 내려받아 **입고·상품 → 엑셀로 일괄 반영**에 올립니다.
- `상품` 시트에 직접 붙여넣습니다. 열 순서는 `코드 | 바코드 | 상품명 | 판매가 | 전산재고 | 실사재고 | 실사일시 | 안전재고 | 메모`입니다.
- **입고·상품 → 상품 추가**에서 하나씩 등록합니다.

**안전재고**를 입력해 두면, 재고가 그 수 이하로 떨어졌을 때 “부족”으로 표시됩니다.

## 연결이 안 될 때 ("처리 중…"에서 멈추거나 "연결 오류")

**⚙️ 설정 → 연결 테스트**를 누르면 원인이 표시됩니다. 흔한 원인은 다음과 같습니다.

1. **배포 액세스 권한이 "모든 사용자"가 아님:** 배포 관리 → 수정 → 액세스 권한을 **모든 사용자**로 바꾸고 **새 버전**으로 배포하세요. "Google 계정이 있는 모든 사용자"로는 동작하지 않습니다.
2. **Code.gs를 고친 뒤 새 버전으로 다시 배포하지 않음:** 배포 관리 → 수정 → 버전: **새 버전**으로 배포하세요.
3. **스크립트가 시트에 연결되지 않음:** script.google.com에서 따로 만든 스크립트는 시트를 찾지 못합니다. 반드시 **시트에서 확장 프로그램 → Apps Script**로 열어서 붙여넣으세요.
4. **비밀번호가 다름:** `Code.gs`의 `PIN` 값과 화면에서 입력한 비밀번호가 같은지 확인하세요.
5. **권한 승인을 하지 않음:** Apps Script 편집기에서 `setup`을 한 번 실행하고 권한을 허용하세요.

## "알 수 없는 오류가 발생했습니다" (구글 시트 화면)

이건 우리 코드가 아니라 **구글 시트가 내는 일반 오류**입니다. 순서대로 확인하세요.

1. **시트 메뉴 → 재고관리 → 🩺 자가 점검**을 눌러 상태를 봅니다. (Apps Script 편집기에서 `selfCheck` 함수를 실행해도 됩니다 — 결과가 실행 기록에 나옵니다.)
2. 브라우저 **새로고침(Ctrl+F5)**, 그다음 **시크릿 창**이나 다른 브라우저로 열어 보기. 확장 프로그램(광고 차단 등)을 끄면 해결되는 경우가 많습니다.
3. 구글 계정이 여러 개면, 시트 주인 계정으로 로그인되어 있는지 확인하세요.
4. 자가 점검의 **전체 칸 수**가 한도(1,000만 칸)의 70%를 넘으면 오래된 날짜 시트를 내려받아 두고 지우세요.
5. 그래도 계속되면 **파일 → 사본 만들기**로 새 사본을 만들면 대부분 풀립니다. (사본에서 Apps Script를 다시 배포해야 합니다.)

> 메뉴용 함수(`priceCheckMenu` 등)를 Apps Script **편집기에서 직접 실행**하면 예전에는 `Cannot call SpreadsheetApp.getUi() from this context` 오류가 났습니다. 지금은 오류 없이 실행 기록에만 결과를 남기고 값은 바꾸지 않습니다. 실제로 적용하려면 **시트의 [재고관리] 메뉴**에서 누르세요.

## 📦 팝업 최종 정산 (마무리하는 날)

사이트 아래쪽 탭 **📦 정산**입니다 (전용 탭이라 한 화면에서 전부 봅니다). 탭을 열면 자동으로 불러옵니다. 전 기간을 한 번에 훑어서 네 가지를 정리합니다.
구글 시트 메뉴 `재고관리 → 📦 팝업 최종 정산 시트 만들기`로도 같은 내용을 `최종정산` 시트로 뽑을 수 있습니다 (업체에 보낼 때 편합니다).

- **① 입고 · 판매 · 남은 재고 검산** — 상품마다 `입고 − 판매 + 환불(변심) − 교환 ± 조정`을 계산해 **전산 재고와 맞는지** 봅니다.
  - 차이가 0이 아닌 줄은 **빨간색**입니다. 기록이 빠졌거나 재고를 두 번 건드린 상품입니다.
  - 불량은 재고로 안 돌아오므로 빼지 않고, 교환은 새로 내준 만큼 빠지는 것으로 계산합니다.
  - 최종 실사가 있으면 **실사 차이**도 같이 보여 줍니다.
- **② 업체 청구 — 불량 · 교환** — `불량` 시트를 원장으로 상품별 합계와 건별 목록을 뽑습니다. **청구 금액 총합**이 바로 나옵니다.
- **③ 반품할 남은 재고** — 팝업 끝나고 업체에 돌려줄 물량입니다. 최종 실사가 있으면 실사 수량, 없으면 전산 재고 기준이고 비고에 표시됩니다. **정가 환산 금액**까지 계산합니다.
- **④ 날짜별 매출** — 첫날부터 마지막 날까지 날짜별 결제 건수·판매 수량·매출·환불·체험 인원과 합계.

- **④ 날짜별 매출 · 체험 티켓** — 날짜별 결제 건수 · **굿즈 수량/매출** · **체험 인원/매출** · 환불 · 합계.
- **⑤ 날짜별 재고 확인** — 상품(세로) × 날짜(가로) 표입니다. 각 칸이 **그날 문 닫을 때 재고**입니다.
  - 지금 전산 재고에서 거꾸로 되짚어 계산합니다 (마지막 날 마감 = 지금 재고, 그 전날 = 다음 날 마감 − 다음 날 움직인 양).
  - **마감 실사가 있는 날은 나란히 비교**해서 다르면 빨간색 + 괄호 안에 그날 실사 수량을 보여 줍니다.
  - 위의 **마감 재고 / 개수 / 금액** 단추로 같은 표를 바꿔 볼 수 있습니다 (개수 = 그날 팔린 수량, 금액 = 그날 팔린 금액).
  - 첫 칸 **시작**은 첫날 열기 전 재고입니다. 입고를 나중에 몰아 넣은 날짜가 있으면 그 전 칸이 음수로 나올 수 있는데, 기록 그대로를 보여 주는 것입니다.

체험 티켓(TK…)은 재고가 없어, 봉투(PK…)는 매장 소모품이라 ①③⑤ 재고표에서는 빠집니다. 둘 다 매출에는 그대로 들어갑니다.

### 업체별 정산

정산 탭 맨 위 **⓪ 업체별 요약**에 업체마다 상품 수 · 입고 · **순판매(수량·금액)** · 업체 청구 · 반품이 나옵니다. 줄이나 아래 업체 단추를 누르면 **그 업체 상품만** ①②③⑤에 보입니다.

- **업체명은 상품 메모 맨 앞**에서 읽습니다. `세영코리아 / 소비자가 8,500` → 세영코리아. 메모 어디든 `업체:이름`이라고 적으면 그게 우선입니다. 비어 있으면 **업체 미지정**.
- **순판매** = 판매 − 돈을 돌려준 환불(변심·불량). 교환은 판매 그대로입니다. 업체 순판매를 다 더하고 봉투를 보태면 굿즈 매출과 1원까지 맞습니다.
- 메모에 `택배 배송` · `주문 배송` · `주문형`이 들어간 상품(캐리어)은 **매장엔 업체 샘플만** 있는 주문 배송 상품이라 반품·재고 검산에서 빠지고 판매 실적만 보입니다.
- **📄 최종 자료 만들기**를 누르면 `최종정산` 시트와 함께 **업체마다 `정산_업체명` 시트**가 생기고, 업체별 PDF 단추가 나옵니다. 업체에 보낼 자료로 그대로 쓰시면 됩니다.

### ⑥ 원가 · 지급 예정 (내부용, v41)

정산 탭 맨 아래 **⑥ 원가**는 기본으로 접혀 있고 **💰 원가 보기**를 눌러야 숫자가 나옵니다 (매장 화면에 원가가 바로 보이지 않게).

- **원가 = 제안서의 공급가 (VAT 별도).** 구글시트 `원가` 시트(코드 · 상품명 · 업체 · 소비자가 · 원가 · 메모)에서 읽습니다.
- **판매 원가** = 순판매 수량 × 원가 → 업체에 줄 돈(VAT 별도). **지급 예정** = 판매 원가 × 1.1.
- **매출이익** = 순매출 ÷ 1.1 − 판매 원가. **반품 재고 원가** = 반품 수량 × 원가.
- 업체 단추를 누르면 그 업체 원가만 보입니다.
- 원가 칸이 비어 있으면 **원가 미정**으로 빨갛게 표시되고, 화면에서 바로 넣을 수 있습니다 (비밀번호 `0921`). `원가` 시트에서 직접 고쳐도 됩니다.
- `원가` 시트의 **업체** 칸을 채우면 상품 메모보다 우선해서 그 업체로 묶입니다 (예: 키캡 → 클래키).
- **📄 최종 자료 만들기**를 누르면 `원가정산` 시트도 함께 생기고 **💰 원가정산 PDF** 단추가 나옵니다.
- 원가는 `최종정산`·`정산_업체명` 시트, 업체별 PDF, CSV에 **들어가지 않습니다.** 다만 **엑셀(xlsx)은 구글시트 전체**라 원가 시트가 들어 있으니 업체에는 업체별 PDF를 보내세요.
- 원가를 넣고 고쳐도 **재고 · 매출은 바뀌지 않습니다.**

### 입고는 '첫날 들어온 수량'으로 계산합니다

정산의 **입고**는 거래 시트의 입고 줄을 더한 값이 아니라, **지금 재고에서 날짜별로 거꾸로 되짚어 구한 첫날 재고 + 기간 중 입고**입니다.
그래서 9/17 입고가 두 번 기록됐거나(재고엔 한 번만 반영), 엑셀로 불러와 입고 기록이 없는 상품도 **첫날 실제로 들어온 수량**이 나옵니다.

날짜별 재고는 **마감 실사가 있는 날은 실사 수량**으로 맞추고 거기서 다시 되짚습니다. 기록에 1개가 빠져도 틀린 숫자가 앞 날짜로 번지지 않고, 그날 칸만 빨간색 `(기록 n)`으로 표시됩니다.

### 재고 표시 [재고±n]

'재고는 그대로'로 처리한 교환·환불·지우기는 거래 메모 끝에 `[재고0]`, `[재고-1]` 같은 표시가 붙습니다. 그 줄이 실제로 재고를 얼마나 움직였는지를 남겨서, 최종 정산이 정확히 되짚을 수 있게 합니다. 지우지 마세요.

### 재고 안 빼고 넣은 결제는 지워도 재고가 안 늘어납니다 (v39)

영수증 직접 입력에서 **"재고도 함께 차감"을 끄고** 넣은 줄에는 메모 끝에 `[재고0]`이 붙습니다. 이 줄을 나중에 🗑 지우기 하면, 원래 재고를 안 뺐으니 **되돌리지도 않습니다.** 결제 수정도 바뀐 수량만큼만 재고를 움직이고 표시를 이어서 관리합니다.

(예전에는 이 경우 지울 때 +1이 되어, 9/20 키캡 4구 중복 줄을 9/21에 넣고 9/22에 지우면서 전산 재고만 1개 늘어났습니다.)

### 기록 손질 (repair)

최종 정산 전에 한 번 쓰는 관리 기능입니다 (비밀번호 `0921`).
- 예전 버전의 '결제 수정'으로 추가된 줄 중 일시가 `Thu Sep 17 2026 …`처럼 깨진 것을 `2026-09-17 21:05:48`로 고칩니다.
- 지정한 줄에 [재고±n] 표시를 붙입니다.
- `logs:[{time, code, qty, memo}]`로 **'기록만' 조정 줄**을 남깁니다. 그때 이미 전산에 반영된 움직임(예: 9/22 중복 줄 삭제로 전산만 +1)을 정산이 알 수 있게 하는 것으로, **재고 숫자는 바꾸지 않습니다.** 같은 줄은 두 번 들어가지 않습니다.
- `dry: true`로 부르면 바꾸지 않고 바꿀 목록만 보여 줍니다.

### 최종 자료 내려받기 (PDF · 엑셀)

**📄 최종 자료 만들기** 단추를 누르면 `최종정산` 시트를 만들고, 바로 아래에 내려받기 단추가 나옵니다.

| 단추 | 받는 것 |
|---|---|
| 📄 PDF로 받기 | `최종정산` 시트를 가로 A3로 뽑은 PDF |
| 📊 엑셀(xlsx)로 받기 | 구글시트 전체를 엑셀 파일로 (원가 시트 포함 — 내부용) |
| 💰 원가정산 PDF | `원가정산` 시트 PDF (내부용) |
| 시트 열기 | 구글시트의 `최종정산` 탭 |
| CSV로 받기 | 화면에 있는 정산 내용을 그대로 CSV로 (구글 로그인 없이도 됩니다) |

PDF·엑셀은 **구글에 로그인된 브라우저**에서 열립니다. 로그인이 안 되어 있으면 CSV를 쓰세요.

## 시트 구조

| 시트 | 내용 |
|---|---|
| `상품` | 현재 재고 마스터. 실사재고가 전산재고와 다르면 빨간색으로 표시 |
| `거래` | 모든 변동 기록(판매/입고/조정/환불). 판매는 결제번호로 묶임 |
| `일별요약` | 날짜별 결제건수·판매수량·매출·객단가·환불·입고·불일치 수 |
| `실사기록` | 실사 상품별 기록. 점검마다 테두리, 날짜가 바뀌면 굵은 선 |
| `실사요약` | 점검 한 번에 한 줄(날짜·구분·일시·담당자·불일치수·차이금액) |
| `불량` | 불량 환불 · 교환 상품 (둘 다 재고로 돌아오지 않음). 맨 끝 `구분` 칸이 `불량`/`교환`. 업체 청구용 집계 |
| `원가` | 상품별 원가(공급가·VAT별도)와 업체. 정산 ⑥ 원가가 여기서 읽습니다 (내부용) |
| `원가정산` | 최종 자료 만들 때 생기는 업체별·상품별 원가·지급 예정·매출이익 (내부용) |
| `수기수정` | 영수증 직접 입력·결제 수정 이력 |
| `판매가수정` | 판매가를 바꾼 이력과 지난 매출 재계산 기록 |
| `매출대사` | 카드 단말기 금액과 맞춰본 기록 (날짜·시각·담당자·실제·시스템·차이·메모) |
| `바코드점검` | 바코드 점검 결과 |
| `YYYY-MM-DD` | 자정(또는 마감)에 만들어지는 그날의 보관 시트. 요약·결제별 판매·체험 티켓·상품별 판매·실사 점검·**재고 점검(오픈·마감)**·전체 거래가 항목마다 테두리로 구분됩니다 |

## 주의

- 입장 비밀번호는 창을 새로 열 때마다 묻습니다. 같은 탭에서 새로고침할 때는 묻지 않고, 상단 🔒 잠금 버튼으로 바로 잠글 수 있습니다. 비밀번호는 브라우저에 저장되지 않습니다.
- 비밀번호는 간단한 잠금 장치일 뿐입니다. 웹 앱 URL과 PIN은 매장 직원에게만 공유하세요.
- 재고는 `거래` 시트의 기록으로 계산되므로, `상품` 시트의 전산재고를 직접 고치면 그 변경은 이력에 남지 않습니다. 가능하면 화면의 **맞추기**나 **엑셀 반영**을 사용하세요.
