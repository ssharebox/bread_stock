기능
판매(결제): 상품을 담아 한 번에 결제하면 결제번호가 생기고 재고가 자동으로 줄어듭니다. 바코드 스캔 후 Enter로도 담을 수 있습니다.
재고: 전산재고 옆에 직접 센 실사 수량을 입력합니다. 두 수량이 다르면 행이 빨간색으로 바뀌고 “재확인” 표시가 붙습니다. 구글 시트에서도 같은 행이 빨간색으로 보입니다. “맞추기”를 누르면 전산재고를 실사 수량으로 바꾸고, 그 차이를 ‘조정’으로 기록합니다.
입고·상품: 입고를 등록하고 상품을 추가합니다. 인포스페이스 창고매장재고 엑셀을 올리면 전산재고를 한꺼번에 반영합니다.
일별 리포트: 날짜별로 결제 건수, 판매 수량, 매출, 결제당 평균 금액, 환불을 보여 줍니다. 결제별 상세 내역(무엇을 몇 개, 얼마에 팔았는지)과 상품별 판매 순위도 볼 수 있고, 결제 단위로 환불하면 재고가 복원됩니다.
자정 자동 보관: 매일 00시에 전날 내역을 2026-09-17 같은 날짜 이름의 새 시트로 내보냅니다. 새 시트에는 요약, 결제별 판매, 상품별 판매, 마감 재고(불일치는 빨간색), 전체 거래가 들어갑니다. 일별요약 시트에도 한 줄씩 누적됩니다.
구글 트리거의 특성상 실행 시각은 00:00~01:00 사이입니다.
바코드 읽기 (PC):
USB/무선 바코드 스캐너: PC에 꽂기만 하면 됩니다. 어느 화면에서든 찍으면 현재 탭에 맞게 처리됩니다.
판매 탭: 결제에 담기
입고·상품 탭: 입고 목록에 +1
재고 탭: 해당 상품을 찾아 실사 칸으로 이동. 수량을 입력하고 Enter를 누르세요.
등록되지 않은 바코드: 경고음이 나고, 상품 추가 칸에 바코드가 미리 채워집니다.
웹캠: 상단의 📷 카메라 스캔 버튼을 누르세요. 처음 한 번 카메라 권한을 허용해야 합니다.
스캐너는 "숫자 입력 후 Enter"(키보드 모드)로 설정되어 있어야 합니다. 대부분 기본값입니다.
샘플 모드: 연결 설정 전에는 샘플 상품으로 모든 기능을 미리 써 볼 수 있습니다. 샘플 데이터는 이 브라우저에만 저장됩니다.
설치 (약 10분)
1. 구글 시트 + Apps Script
새 Google 시트를 만듭니다. 이름은 예를 들어 브레드이발소 재고로 합니다.
확장 프로그램 → Apps Script를 엽니다. 기본 코드를 지우고 apps-script/Code.gs 내용을 붙여넣은 뒤 저장합니다.
위쪽 함수 선택에서 **setup**을 고르고 실행합니다. 권한 요청이 나오면 허용합니다.
상품, 거래, 일별요약 시트가 만들어지고 자정 보관 트리거가 등록됩니다.
PIN을 바꿉니다. 왼쪽 ⚙️ 프로젝트 설정 → 스크립트 속성에서 PIN 값을 원하는 숫자로 바꾸세요. 기본값은 0000입니다.
배포 → 새 배포 → 유형: 웹 앱을 선택하고 다음과 같이 설정합니다.
다음 사용자 인증 정보로 실행: 나
액세스 권한: 모든 사용자
배포 후 나오는 웹 앱 URL(https://script.google.com/macros/s/…/exec)을 복사해 둡니다.

Code.gs를 고친 뒤에는 배포 관리 → 수정(연필) → 버전: 새 버전으로 다시 배포해야 반영됩니다. 이렇게 하면 URL은 그대로 유지됩니다.

2. GitHub Pages
GitHub에서 새 저장소를 만듭니다. 예: bread-inventory
index.html을 업로드합니다. README.md와 apps-script/ 폴더도 함께 올려 두면 관리하기 편합니다.
저장소에서 Settings → Pages → Branch: main / (root) → Save를 누릅니다.
1~2분 뒤 https://<아이디>.github.io/bread-inventory/로 접속합니다.
3. 연결

웹 앱 URL은 index.html에 기본값으로 들어 있습니다. 접속한 화면에서 ⚙️ 설정 탭을 열고 PIN과 담당자 이름만 입력한 뒤 저장하고 연결을 누릅니다. 상단 배지가 “구글 시트 연결됨”으로 바뀌면 완료입니다. 매장 휴대폰마다 한 번씩 설정하면 됩니다.

4. 첫 상품 넣기

다음 중 하나를 사용하세요.

인포스페이스에서 브레드이발소 창고매장재고 엑셀을 내려받아 입고·상품 → 엑셀로 일괄 반영에 올립니다.
상품 시트에 직접 붙여넣습니다. 열 순서는 코드 | 바코드 | 상품명 | 판매가 | 전산재고 | 실사재고 | 실사일시 | 안전재고 | 메모입니다.
입고·상품 → 상품 추가에서 하나씩 등록합니다.

안전재고를 입력해 두면, 재고가 그 수 이하로 떨어졌을 때 “부족”으로 표시됩니다.

연결이 안 될 때 ("처리 중…"에서 멈추거나 "연결 오류")

⚙️ 설정 → 연결 테스트를 누르면 원인이 표시됩니다. 흔한 원인은 다음과 같습니다.

배포 액세스 권한이 "모든 사용자"가 아님: 배포 관리 → 수정 → 액세스 권한을 모든 사용자로 바꾸고 새 버전으로 배포하세요. "Google 계정이 있는 모든 사용자"로는 동작하지 않습니다.
Code.gs를 고친 뒤 새 버전으로 다시 배포하지 않음: 배포 관리 → 수정 → 버전: 새 버전으로 배포하세요.
스크립트가 시트에 연결되지 않음: script.google.com에서 따로 만든 스크립트는 시트를 찾지 못합니다. 반드시 시트에서 확장 프로그램 → Apps Script로 열어서 붙여넣으세요.
PIN이 다름: 스크립트 속성의 PIN과 화면에 입력한 PIN이 같은지 확인하세요.
권한 승인을 하지 않음: Apps Script 편집기에서 setup을 한 번 실행하고 권한을 허용하세요.

주의
PIN은 간단한 잠금 장치일 뿐입니다. 웹 앱 URL과 PIN은 매장 직원에게만 공유하세요.
재고는 거래 시트의 기록으로 계산되므로, 상품 시트의 전산재고를 직접 고치면 그 변경은 이력에 남지 않습니다. 가능하면 화면의 맞추기나 엑셀 반영을 사용하세요.
